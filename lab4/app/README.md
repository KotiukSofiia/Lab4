# Конспект-помічник на локальній LLM

Консольний застосунок, який за вашим навчальним текстом (конспект лекції, статтю, розділ підручника):

- робить **стислий конспект** (`/summary`);
- генерує **тест у форматі JSON** і перевіряє ваші відповіді (`/quiz 5`);
- **відповідає на питання** за текстом з урахуванням історії діалогу й чесно каже «У тексті цього немає», якщо відповіді в тексті немає.

Модель працює **локально** через OpenAI-сумісний API (Ollama за замовчуванням). Жодних хмарних сервісів.

## Запуск

```bash
# 1. Встановіть Ollama: https://ollama.com/download (або brew install ollama)
# 2. Запустіть сервер з контекстом 8192 токени
OLLAMA_CONTEXT_LENGTH=8192 OLLAMA_NUM_PARALLEL=4 OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 ollama serve
# (якщо відкритий застосунок Ollama — спершу закрийте його, щоб порт 11434 був вільний)
# 3. Завантажте модель (див. звіт, розділ «Вибір моделі»)
ollama pull qwen3:4b-instruct-2507-q4_K_M
# 4. Встановіть залежність і запустіть застосунок
pip install -r requirements.txt
python study_helper.py --file sample_lecture.txt
```

Аргументи: `--base-url` (або `LLM_BASE_URL`, за замовч. `http://localhost:11434/v1`), `--model` (або `LLM_MODEL`),
`--reasoning-effort none|low|medium|high` (за замовч. `none` — вимикає міркування в гібридних моделях на кшталт qwen3),
`--file` — текст, який одразу завантажити. Працює також з llama-server / LM Studio: достатньо змінити `--base-url`.

## Команди

| Команда | Що робить |
|---|---|
| `/load <файл>` | завантажити `.txt`/`.md` як контекст |
| `/paste` | вставити текст вручну, закінчити рядком `END` |
| `/summary` | конспект із 5–7 пунктів |
| `/quiz [N]` | N тестових питань (1–10), інтерактивна перевірка |
| `/clear` | очистити історію діалогу |
| текст без `/` | питання за текстом |

## Параметри генерації та їх обґрунтування

| Режим | temperature | max_tokens | Чому |
|---|---|---|---|
| питання за текстом | 0.3 | 600 | відповіді мають бути фактичними й стабільними; невелика температура лишає природність мови. 600 токенів ≈ 2–3 абзаци українською — достатньо для розгорнутої відповіді й не дає моделі «зациклитися» |
| конспект | 0.2 | 500 | конспект має бути відтворюваним; 5–7 пунктів по реченню ≈ 250–400 токенів |
| тест (JSON) | 0.4 | 900 | трохи вища температура дає різноманітніші питання й дистрактори; 5 питань з поясненнями ≈ 600–800 токенів |

- **Контекст — 8192 токени** (`OLLAMA_CONTEXT_LENGTH=8192`). Вхідний текст обмежено 12 000 символів (≈ 4–5 тис. токенів українського тексту для токенізатора Qwen3), ще ~1 тис. — системний промпт та історія (останні 6 обмінів), решта — відповідь. Більший контекст збільшив би KV-кеш і памʼять (див. розрахунок у звіті), а для конспекту однієї лекції не потрібен.
- **max_tokens задано завжди** — без нього мала модель може генерувати нескінченно. Якщо відповідь обрізано лімітом, застосунок про це попереджає.
- `reasoning_effort: none` — режим міркування вимкнено: для цих задач він лише додає затримку (див. відповідь на питання 8–9 у ноутбуці).

## Зворотний звʼязок і помилки

- До першого токена показується анімований індикатор «Модель думає…», далі відповідь **стрімиться** в термінал; після відповіді — TTFT і повний час.
- Зрозумілі повідомлення для: сервер не запущено (`APIConnectionError` → підказка `ollama serve`), таймаут 120 с, модель не знайдена (підказка `ollama pull ...`), HTTP-помилки сервера, порожня відповідь, невалідний JSON у тесті (автоматичний повторний запит з проханням виправити, потім повідомлення), файл не знайдено / не UTF-8, задовгий текст (обрізання з попередженням).

## Додаткові можливості

Системний промпт, few-shot приклад у промпті тесту, JSON-вихід з валідацією схеми, багатокроковий ланцюжок (генерація → перевірка → повтор), робота з файлами, історія діалогу.
